# ADB 自动连接 · 流程说明（local-adb-quiet 0.1.0）

配套：本仓库的 `README.md`（总览）、`lib/`（源码）、`local-adb-quiet-0.1.0.tgz`（发布包）。

> 本版依据 2026-11-13 在 Redmi `26048RP6AC` / Android 16（SDK 36）/ dsh `0.2.2-rc.1` 的实测修订，
> 与更早草稿的差异集中在第四、五节（Android 11+ 无线调试 TLS 通道）和第七节排障。

---

## 一、装到另一台机器的流程

```
① 拷贝 tgz 到目标机（建议 /root/，路径别带中文空格）
② dsh plugin --profile web add /root/local-adb-quiet-0.1.0.tgz
      → 输出 "+ local-adb-quiet 0.1.0" 即成功；命令会自动登记进 profile 的 bundle 列表
③ App：设置 → 引擎 → 重启引擎
④ 输入框上方出现「ADB 未连接 · 点按」→ 点开 → 「连接」
      → 手机弹「允许 USB 调试吗」→ 允许 + 勾「始终允许使用这台计算机」
⑤ 状态条变成「ADB · <端口>」，bash 里就能直接 adb shell
```

前置条件：App ≥ 1.0.11；dsh 运行时 ≥ 0.2.1-rc.2 且 < 0.3.0（`dsh --version` 查）；
手机侧 TCP 调试已开（Stellar / Shizuku 的 TCP，或做过 `adb tcpip <port>`）。

实测补充：

- `dsh plugin --profile web add <tgz>` 会在 `profiles/web/package.json` 写入
  `"local-adb-quiet": "file:/…/local-adb-quiet-0.1.0.tgz"` 并追加到 `dsh.profile.bundles`；
  `dsh --profile web --dump-config` 能直接看到 `- id: local-adb-quiet`，用来确认登记成功。
- **第 ③ 步可以先跳过**：装完运行中的引擎就会挂上 `adb` 工具（`adb devices` 立即走插件链路）。
  只有输入框上方的状态条/面板没出现时，才需要重启引擎刷新前端。
- 目标机若没有 adb 客户端，插件会在点「连接」时 `apt-get install -y adb`。proot 环境里若
  `/usr/share/man/man1` 不存在（裁剪镜像常见），apt 会在 openjdk 依赖上留半配置状态，
  先 `mkdir -p /usr/share/man/man1 && dpkg --configure -a` 再重试。
- 动手前备份：`cp profiles/web/package.json{,.bak}`、`cp profiles/web/cordis.patch.yml{,.bak}`；
  卸装 `dsh plugin --profile web remove local-adb-quiet`。

## 二、运行期流程（自动连接是怎么发生的）

### 1. 前提
手机上的 adbd 已经通过 TCP 监听（Shizuku 类管理器或 `adb tcpip` 打开）。端口由系统随机分配，
重启或服务重开会变。插件不启动 adbd、不需要 root，只负责“找到并连上”。

### 2. 探端口：发协议握手，不看端口号
`lib/adb.js`，纯 Node 实现，查找阶段不需要 adb 二进制：

- 向候选端口发标准 ADB `CNXN` 包：
  - 24 字节头：`command(CNXN) | arg0(协议 1.0.0) | arg1(max payload 256K) | length | crc32 | magic(^0xffffffff)`
  - payload：`host::\0`（声明自己是 host）
- 真 adbd 会回 `AUTH`（要密钥）或 `CNXN`（`device::` banner）；其他服务关连接或超时
- 探测顺序：记忆端口 → 3455 → 5555（约几十毫秒）
- 都不通才全端口扫 1–65535：400 并发、单口 280ms 超时，跳过 3080（App web）和 5037（adb server）
- 两个防误判：
  - TCP 自连：内核可能把目标端口选成本地源端口，socket 在跟自己说话 → 判 `localPort === port` 直接否
  - 自连回显的 banner 是 `host::` → 回包只认 `device::`

> 实测：这套明文握手在 Android 16 的**无线调试（TLS）端口上一律拿不到应答**，
> 扫描结果表现为“全端口无开放端口”，属于正常现象——见第四节。

### 3. connect 与授权
`doConnect()`（`lib/index.js`）：

1. `resolveAdb()` 找 adb 客户端；没有且允许安装时 `apt-get install -y adb`
2. 已经连着（`adb devices -l` 里有匹配的 TCP 设备且 state=device）→ 直接返回
3. `discoverPort()` 找端口，找不到返回 `no-port`
4. `adb connect 127.0.0.1:<port>`
5. 每 1.2 秒读 `adb devices -l`，用 `pickDevice()` 挑出 TCP serial 且端口匹配的那条：
   - `state=device` → 成功，写 `port/authorized:true`
   - `state=unauthorized|authorizing` → 状态条转「待授权」，最多等 45 秒
6. 超时记 `authWaitUntil = now + 10min`，这 10 分钟内不再自动催授权，免得反复弹窗

等待时长按入口区分：面板点「连接」20 秒、引擎启动自动连 6 秒、扫描后再连 15 秒。

### 4. 自愈与记忆
- 运行记忆写到 `$DSH_HOME/dsh-go/adb-link/state.json`：`port / authorized / auto / authWaitUntil / lastError`
- 触发自动重连的时机：引擎启动（`apply()` 里最先跑 `maybeAutoConnect()`）、状态条/面板挂载、轮询发现 `disconnected`
- 防抖：`AUTO_COOLDOWN_MS = 90s`；自动连不扫描（只试记忆端口和 3455/5555）
- 端口漂移：自动连返回 `no-port` 且曾经授权过 → 后台全端口重扫，`SCAN_RETRY_MS = 10min` 限频
- 并发：`connectOnce()` 用 `rt.inflight` 去重，多个入口共享同一次尝试

### 5. 状态刷新
- `snapshot()` 读一次真实 adb 状态，缓存 1.5 秒
- 状态条每 12 秒、面板每 6 秒轮询；有状态变更时 `bump()` 立即推给所有订阅者
- 除了轮询，还有事件驱动（连接/断开/扫描/安装中都会 invalidate 并 bump）

### 6. 与 bash、AI 的关系
- 插件和 bash 共用 adb server `127.0.0.1:5037`，插件等价于替 bash 执行了一次 `adb connect`
- 系统提示段：插在 `TOOL_BASH` 之后，连上后告诉模型“通道就绪，系统级操作主动用 adb，不先问用户”
- `adb` 工具：`args` 原样传给 adb、不经过 shell；执行前若未连接会先自动连一次（最多 8 秒）；
  失败返回具体原因（`no-adb` / `no-port` / `unauthorized`）和下一步动作

## 三、参数总表

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `KNOWN_PORTS` | 3455, 5555 | 优先探测 |
| `PORT_EXCLUDE` | 3080, 5037 | 扫描跳过 |
| `SCAN_START/END` | 1 / 65535 | 扫描范围 |
| `SCAN_CONCURRENCY` | 400 | 明文扫描并发 |
| `PAIR_SCAN_CONCURRENCY` | 300 | TLS 候选扫描并发（实测 800 会漏检） |
| TLS 分块 | 4096 | 块内 TCP 探测，块间做 TLS 握手 |
| 早停 | 3 个候选 | 凑够 TLS 候选即停 |
| `SCAN_TIMEOUT_MS` | 280 | 单口探测超时 |
| `CONNECT_WAIT_MS` | 45000 | 授权等待（默认） |
| `CONNECT_WAIT_PENDING_MS` | 20000 | 面板点按时 |
| `AUTH_COOLDOWN_MS` | 10 min | 授权超时后冷却 |
| `AUTO_COOLDOWN_MS` | 90 s | 自动重连防抖 |
| `SCAN_RETRY_MS` | 10 min | 端口漂移重扫间隔 |
| `STRIP_POLL_MS` / `PANEL_POLL_MS` | 12 s / 6 s | 界面刷新 |
| snapshot TTL | 1.5 s | 状态缓存 |

## 四、两条通道：经典 TCP 与 Android 11+ 无线调试（TLS）

| | 经典 ADBoverTCP（`adb tcpip` / Stellar·Shizuku TCP） | 无线调试（Android 11+，TLS 配对） |
| --- | --- | --- |
| 协议 | 明文 `CNXN`/`AUTH` | TLS，`adb pair` 换证书 |
| 插件能自动探到吗 | 能（`lib/adb.js` 握手） | **不能**，握手包被 TLS 直接丢 |
| 怎么接 | 面板点「连接」 | `adb pair` + `adb connect`（下表） |
| 端口稳定性 | 随机，重启变 | 随机，重开开关/重启变 |

无线调试接入（一次配对，之后免码）：

```sh
# 手机：开发者选项 → 无线调试（保持与 DSH 同一 Wi-Fi）
# 屏上「使用配对码配对设备」给出 IP:配对端口 + 6 位配对码
adb pair 192.168.1.20:44285 902415      # 一次性；配对记录存 ~/.android/adb_known_hosts.pb
# 连接端口是另一个随机数，扫出来（或用屏上「IP 地址和端口」）
adb connect 192.168.1.20:43955
adb devices -l                          # 出现 device 即可用
```

关键点：无线调试的 adbd 监听 `0.0.0.0:<connect port>`，所以 `adb connect 127.0.0.1:<port>`
同样成立。这意味着：

- 插件的 `pickDevice()` 能匹配到这条 `127.0.0.1:<port>` 设备，状态条正常显示「已连接」；
- `state.json` 的 `port` 填这个端口，下次引擎启动 `maybeAutoConnect()` 直接复用；
- bash 与插件 `adb` 工具共用 `127.0.0.1:5037`，都通。

实测记录（2026-11-13）：

- `adb pair 192.168.1.20:44285 902415` → `Successfully paired [guid=adb-8LXC7X8LORGUIF9D-…]`
- 全端口扫描：22s 左右出结果；`135`、`44652` 是瞬时报文/误报（`adb connect` 后 refused），
  真端口 `43955` 一次连上，`192.168.1.20:43955 device` + `127.0.0.1:43955 device`
- 14 分钟后旧连接全部 `Connection refused`，端口漂到 `35753`：**“断联”其实是端口轮换**，
  配对记录还在，重扫即恢复，不需要新配对码。

## 五、断联恢复（`adb-link.sh`）

`bash /root/workspace/adb-link.sh <HOST> [PAIR_CODE]`（手机端副本：
`/sdcard/Download/DSH-Go/adb-link.sh`）。逻辑：已知端口 → 全端口扫描 → 逐个 `adb connect`；
给了配对码且都失败时再 `adb pair`。

```sh
bash adb-link.sh 192.168.1.20              # 日常重连（已配对过）
bash adb-link.sh 192.168.1.20 902415       # 新配对码 / 重新配对后
```

| 退出码/输出 | 含义 | 处理 |
| --- | --- | --- |
| `connected: HOST:PORT` | 成功 | 无需动作 |
| `没有开放端口` | 无线调试关了、端口没开、或不在同一 Wi-Fi | 手机上重开无线调试 |
| `扫到端口但连不上` | 没点「允许调试」/ 配对失效 | 点弹窗，或带配对码再跑 |
| 连上但 `unauthorized` | 授权未完成 | 面板点「连接」+ 手机上允许 |

## 六、边界（修订）

- 经典 ADB over TCP：插件全自动（握手探测 → connect → 授权等待）。
- Android 11+ 无线调试：**插件不会自动发现**（TLS 握手探不到），但用 `adb pair` 配对后照样能跑，
  只是首次配对和端口扫描要靠 bash/脚本；配对完成后插件的状态条、自动重连、`adb` 工具都正常。
- 只连 `127.0.0.1`，不扫局域网、不连其他设备（无线调试因 adbd 监听 `0.0.0.0` 而恰好适用）。
- 权限等于普通 `adb shell`（`uid=2000(shell)`、`u:r:shell:s0`），不是 root；
  不读剪贴板、输入框、对话内容。
- 首次必须点一次「允许」并勾「始终允许」，否则每次重连都弹窗。

## 七、排障对照

| 现象 | 大概率原因 | 动作 |
| --- | --- | --- |
| 状态条「ADB 未连接」 | 端口变了 / TCP 服务没开 | 点「扫描端口」；确认 Stellar 的 TCP 已开 |
| 昨天好好的今天全端口扫不到 | Android 11+ 无线调试是 TLS，明文握手拿不到应答 | 点「扫描端口」会自动转 TLS 探测；或走第四节 `adb pair` + `adb connect` |
| 配对端口不知道填什么 | 无线调试面板每次打开都换端口 | **留空**即可：插件扫高位端口段，用 `adb pair` 逐个试（配对码只对真正的配对端口有效，试错不会配错设备） |
| 之前 `device`，突然 `Connection refused` | 无线调试端口轮换（实测 43955 → 35753） | `bash adb-link.sh <HOST>` 重扫 |
| 一直「待授权」 | 弹窗没点或没勾始终允许 | 点「连接」→ 手机上允许 |
| 「缺 adb 客户端」 | 运行时升级清了 /usr | 点「连接」自动装；失败先 `mkdir -p /usr/share/man/man1 && dpkg --configure -a` |
| 装插件报版本不兼容 | dsh 不在 0.2.1-rc.2 – 0.2.x | 换机器或用市场版 `dsh-go-adb-link` |
| bash 里 adb 不通但状态条已连接 | 另一个 adb server 在跑 | `adb kill-server && adb connect 127.0.0.1:<port>` |
| `adb devices` 出现 `offline` 重复条目 | 误报端口留下的死 transport | `adb disconnect <HOST:PORT>` |
